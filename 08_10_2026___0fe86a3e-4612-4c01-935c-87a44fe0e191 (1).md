# **Practical Exam 2 – Task Management App: Authentication, Teams & Real-Time Chat**

## **Objective**

Extend the Task Management app built in Practical Exam 1 by adding user accounts, real Team functionality, and a real-time chat feature, all backed by Firebase. This exam focuses on:

*   Adding Firebase Authentication (sign up, login, logout) and protecting screens behind login
*   Building real Team functionality (create/join a team, team members list) to replace the Assignment 1 placeholder
*   Linking tasks to teams and to a specific assignee (team member)
*   Building a real-time chat screen per team using Firestore
*   Producing a written report with screenshots and Firebase console evidence, since the app will be assessed mainly through the report, not by running the app live

## **Starting Point**

Continue from your Practical Exam 1 project (same GitHub repository and Firebase project). Keep the existing Task CRUD functionality working — you are adding authentication and access control on top of it, not rebuilding it from scratch.

## **Functional Requirements**

**1\. Firebase Authentication**

*   Enable Email/Password sign-in in the Firebase Authentication console (Google Sign-In is optional bonus).
*   Build a Sign Up screen (name, email, password) that creates a Firebase Auth user and a matching document in a users collection in Firestore (fields: id, name, email, avatarUrl, createdAt).
*   Build a Login screen (email, password) that signs the user in with Firebase Auth.
*   Implement Logout functionality (e.g. from the Profile screen).
*   Persist the authentication state across app restarts (e.g. using Firebase Auth's onAuthStateChanged listener) so a logged-in user is not asked to log in again immediately.
*   Protect the Home, Teams, and Chat screens so they are only reachable when a user is logged in; unauthenticated users should be redirected to the Login screen.

**2\. Teams (replacing the Assignment 1 placeholder)**

*   Build a real Teams screen: a logged-in user can create a new team (name, description) or join an existing team (e.g. by team code or by selecting from a list).
*   Store teams in a teams collection (fields: id, name, description, ownerId, createdAt).
*   Store team membership in a teamMembers collection or as a members array/subcollection (fields: teamId, userId, role, joinedAt), linking users to teams.
*   Build a Team Detail screen listing the team's members (name/email) and the team's tasks.

**3\. Tasks Linked to Teams and Assignees**

*   Update the Task creation/edit form from Practical Exam 1 so a task can now be assigned to a team (teamId) and to a specific team member (assigneeId), selected from a dropdown/picker.
*   On the Home or Team Detail screen, show the assignee's name on each task.
*   Only team members should be able to view, create, edit, or delete tasks that belong to that team (this can be enforced in the UI logic and, ideally, in Firestore Security Rules).

**4\. Real-Time Chat**

*   Build a Chat screen accessible from each Team Detail screen (one chat per team).
*   Store chat messages in a Firestore subcollection, e.g. teams/{teamId}/messages, with fields: id, senderId, senderName, text, createdAt.
*   Display messages in a scrollable list ordered by createdAt, showing sender name and message text; visually distinguish the current user's own messages from others'.
*   Use a real-time Firestore listener (onSnapshot) so new messages from any team member appear automatically without a manual refresh.
*   Include a text input and send button to post a new message to the team's chat.

**5\. Firestore Security Rules**

*   Update the Firestore Security Rules so that reading and writing tasks, teams, and messages requires an authenticated user (replace the open/test-mode rules used in Practical Exam 1).
*   At minimum, rules should require request.auth != null for read/write access to these collections.

## **UI / Screen Requirements**

*   Login screen and Sign Up screen, with basic form validation and error messages (e.g. wrong password, email already in use).
*   Home screen (task list), now only reachable after login, showing tasks for the teams the user belongs to.
*   Teams screen (create/join team) and Team Detail screen (members + team's tasks).
*   Chat screen for a team, with message list and input box.
*   Profile screen showing the logged-in user's name/email and a Logout button.
*   A basic shared layout/navigation (tab bar or drawer) that adapts based on whether the user is logged in or not.

## **Optional Features (for bonus marks)**

*   Add Google Sign-In as an alternative login method.
*   Allow the user to upload/select a profile picture (stored in Firebase Storage) shown in the Profile screen and next to chat messages.
*   Add a simple typing indicator or "last seen" status in the chat screen.
*   Add push notifications (e.g. via Expo Notifications) for new chat messages or task assignments.
*   Add a basic ERD/schema diagram covering users, teams, teamMembers, tasks, and messages to the repository README.

## **Tech Stack**

*   Frontend: React Native with Expo (TypeScript)
*   Navigation: React Navigation, with an auth-aware navigator (auth stack vs. app stack/tabs)
*   Backend / Database: Firebase Authentication, Cloud Firestore (and optionally Firebase Storage)
*   State management: React Context (or Redux/Zustand) for the current auth/user state
*   Version Control: Git & GitHub (continue the same repository from Practical Exam 1)
