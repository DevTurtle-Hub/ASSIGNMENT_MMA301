# **Practical Exam 1 – Task Management App: React Native, Firebase Setup & CRUD (No Authentication)**

## **Objective**

Build the technical foundation of a mobile Task Management application using React Native (Expo), connected to Firebase for data storage. The focus of this exam is on:

*   Project scaffolding and folder structure for a React Native (Expo) app
*   Version control with Git and GitHub
*   Connecting the app to a Firebase project (Firestore Database)
*   Designing a simple data model for tasks
*   Building a public (no login required) CRUD screen for tasks
*   Producing a written report with screenshots, since the app will be assessed mainly through the report and Firebase console, not by running the app live

## **Functional Requirements**

**1\. Project Initialization**

*   Create a new React Native project using Expo (TypeScript template).
*   Organize the project using a clean folder structure, e.g. app/ (or screens/), components/, services/, navigation/, assets/.
*   Install and configure ESLint and Prettier for consistent code style.
*   Add a .env.example file (or firebaseConfig.example.ts) listing required Firebase configuration keys, without real secrets.

**2\. Version Control (Git & GitHub)**

*   Initialize a Git repository in the project (git init).
*   Create a .gitignore that excludes node\_modules, .env, .expo, build outputs, etc.
*   Make an initial commit with a clear message (e.g. "chore: initial project setup").
*   Create a public GitHub repository and push your code.
*   Continue committing regularly as you complete each step below (at least 5 meaningful commits).

**3\. Firebase Project & Data Setup**

*   Create a free Firebase project in the Firebase Console.
*   Enable Cloud Firestore (in test mode is acceptable for this exam, since there is no authentication yet).
*   Install the Firebase SDK (firebase or @react-native-firebase/\*) and configure it in a dedicated service file (e.g. services/firebase.ts).
*   Define the initial data model for a tasks collection in Firestore, including at least the following fields on each task document:
    *   id (document ID, auto-generated), title, description, status, priority, dueDate, createdAt
*   teamId and assigneeId fields may be left empty/null for now — they will be used starting in Practical Exam 2.
*   Use the Firebase Console (Firestore Data tab) to confirm the collection and manually add a few sample task documents.

**4\. Home Screen**

*   Build a Home screen that introduces the app (name, short description) and also displays the task list (see section 5 below).
*   Include a simple bottom tab or drawer navigation with placeholder tabs (Home, Teams, Profile) — Teams and Profile can remain non-functional at this stage.
*   Add a simple, responsive layout that looks correct on both a phone-sized and a tablet-sized screen/emulator.

**5\. Simple Task CRUD (No Authentication)**

To practice connecting the app to Firebase end-to-end, implement a simple, public task list directly on the Home screen. No login or authentication is required for this exam — any user of the app can create, view, update, and delete tasks.

*   Use the tasks collection already defined above (title, description, status, priority, dueDate). The teamId and assigneeId fields can stay empty for now.
*   Implement the following on the Home screen:
    *   A form/modal to create a new task (at minimum: title, optional description, optional status)
    *   A list of all tasks, fetched from Firestore and displayed on the Home screen
    *   The ability to edit an existing task (e.g. update its title, description, or status)
    *   The ability to delete a task from the list
*   Implement the Firestore read/write logic in a dedicated service/hook (e.g. services/taskService.ts or hooks/useTasks.ts) covering: list tasks, create task, update task, delete task.
*   The task list should update automatically after a create, update, or delete action, ideally using a real-time Firestore listener (onSnapshot) rather than a manual refresh.

## **UI / Screen Requirements**

*   Home screen with app title, short description, and navigation bar/tabs.
*   A basic shared layout (header and, if applicable, footer/tab bar) used across screens.
*   On the Home screen: a "Create Task" form and a list of existing tasks, each with Edit and Delete actions.
*   A simple "Coming soon" placeholder screen for the Teams section (to be built in Practical Exam 2).
*   A simple Profile placeholder screen (to be built in Practical Exam 2).

## **Optional Features (for bonus marks)**

*   Add simple client-side validation to the task form (e.g. title required).
*   Add a status filter (e.g. show only "To Do" or "Done" tasks) on the Home screen.
*   Add pull-to-refresh on the task list.
*   Add a simple CI check (e.g. GitHub Actions) that runs lint/type-check on every push.
*   Add a basic ERD (Entity Relationship Diagram) or schema diagram of your Firestore data model to the repository README.
*   Use a UI/component library (e.g. React Native Paper, NativeBase, Tamagui) for styling.

## **Tech Stack**

*   Frontend: React Native with Expo (TypeScript)
*   Navigation: React Navigation (bottom tabs or drawer)
*   Backend / Database: Firebase (Cloud Firestore)
*   Version Control: Git & GitHub
*   Testing the app: Expo Go on a physical device, or an Android/iOS emulator
